| 결과물 | 체크리스트 | **수강생이 가져갈 "작은 작품" 1개 명시** + 비포/애프터 |

## 2. 필요유무 판단 — 마스터 프롬프트 항목별

판단 기준: ① 매시간 **자동 작성**으로 실제 지킬 수 있는가 ② 존(한국어 교사·AI 강사)이 **바로 배우고 가르치는 데** 필요한가 ③ 사실과 다른 내용을 만들 위험이 없는가.

### 2-1. ✅ 채택 (그대로 필수 적용)

| 마스터 항목 | 적용 방식 |
|---|---|
| 0장 절대 원칙 5가지 | 전부 채택. 검증 스크립트가 빠진 칸을 막음 |
| 2장 대상 배지 (학습자 3 + 강사 3) | `learner_levels`, `instructor_levels` 필드 |
| 3장 직업군 JOB 코드 14종 | `jobs` 필드 (1~4개) |
| 4장 카테고리 CAT-01~12 | `categories` 필드 (첫 번째가 교안 ID의 CAT) — 기존 7분야 대체 |
| 5장 표준 양식 전 섹션 | 6장 필드로 1:1 대응 |
| 6장 작은 작품 규칙 | 30분 이내, 결과물 명시, 따라하기 → 내 것 만들기 → 도전과제 3단, 무료 경로 우선 |
| 7장 평가 루브릭 | 공통 루브릭을 사이트가 자동 표시, 교안별 맞춤 루브릭은 선택 |
| 8장 사실 확인 규칙 | 1차 출처만, 모든 수치에 확인일, 추측 표현 금지, 국내 사용 여부 확인 |
| 9장 품질 체크리스트 | 검증 스크립트 + 예약 작업 지시문에 반영 |
| 10장 용어 통일 | 첫 등장 "한글(영문)", 서비스·기능명은 공식 표기 |
| 11-2 윤리·저작권·보안 1페이지 | `theory.safety` 필수 (3개 이상) |
| 11-4 유효기간·버전 관리 | `checked`, `review_by`, `version`, 변경 시 `notice` |
| 샘플의 "기능 출시 타임라인" | `timeline` 필수 → 릴리즈 노트 페이지와 연동 |
| 샘플의 비포/애프터 실습 구조 | 실습 설계 권장 패턴으로 채택 |

### 2-2. 🔧 조정 (자동 체계에 맞게 바꿔 적용)

| 마스터 항목 | 원래 요구 | 조정 내용과 이유 |
|---|---|---|
| 1장 3단계 배포 (속보/표준/심화) | D+1 속보, D+3 표준, D+14 심화 | 매시간 작업은 **📘표준 교안 하나로 통일**. 속보 역할은 **카카오톡 알림 + 릴리즈 노트 항목**이 대신함. 심화 패키지는 요청할 때 별도 제작 |
| 9장 "작성자가 직접 재현" | 사람이 처음부터 끝까지 실행 | 자동 작성은 실제 서비스에 로그인해 실행할 수 없음. **공식 문서 기준으로 작성하고, 재현하지 못한 메뉴 경로·결과는 `[확인 필요]` 표시** + 강의 전날 체크리스트를 강사 노트에 넣어 강사가 확인 |
| 2-0 완성 작품 미리보기 이미지·화면 캡처 | 이미지·캡처 | 자동 작성은 캡처 불가 → **텍스트 예시 결과물** + "강사가 사전 캡처" 안내로 대체 |
| 1-5 요금 | 요금제·제한 | v1의 `pricing`(무료/유료 배지 + 요금제별 기능) 유지. 가격은 공식 페이지 표기 그대로, 한국 원화 가격은 확인될 때만 |
| 11-5 대상 특화 버전 | 별도 버전 제작 | 별도 파일 대신 **강사 노트의 레벨별 변형 가이드**에 시니어·다문화(한국어 학습자) 변형을 넣음 |
| 11-9 신기능 모니터링 | 담당자 지정·주간 브리핑 | **매시간 작업이 공식 릴리스 노트를 훑어 `releases.json`에 출시일을 기록**. 교안은 그중 아직 교안이 없는 항목에서 우선순위(사용자 수·무료 가능성·강의 수요·실습 가능성)로 1개 선택 |
| 제출물 4종 | 학습자본·강사본·결과물·프롬프트 모음 | 사이트에서 **학습자용/강사용 보기 전환**, PPT도 **학습자용/강사용(멘트는 발표자 노트)** 2종, **복붙 프롬프트 모음 .txt** 다운로드 |

### 2-3. ⏸ 보류 (지금 자동 교안에는 불필요 — 필요하면 별도 시리즈로)

| 마스터 항목 | 보류 이유 |
|---|---|
| 11-1 공통 기초 모듈 (검증법·프롬프트 5요소·도구 선택) | 신기능 교안이 아니라 고정 교안. 한 번 만들면 되므로 매시간 작업과 분리해 **요청 시 시리즈로 제작** (교안의 "다음에 배울 것"에서 연결) |
| 11-3 강사 전용 트랙 (계약·견적·포트폴리오·로드맵) | 신기능과 무관한 강사 경력 콘텐츠 → 별도 시리즈 |
| 11-6 비용 리터러시 (기관 월 비용 시뮬레이션) | 교안마다 요금제 표로 기본 대응. 시뮬레이션은 CAT-12 비교 교안에서 다룸 |
| 11-7 국비·지자체 서식 연동 | 교육계획안 스킬로 별도 작성 가능, 교안 본문엔 불필요 |
| 11-8 피드백 순환 (강사 피드백 폼) | 사용자 1인 운영 단계라 불필요. 강의 후 수정 요청은 대화로 받아 `version`을 올림 |

### 2-4. 운영 판단

- **매시간 1개 유지**: 다만 표준 교안은 분량이 커서, 새 출시가 없으면 억지로 만들지 않고 **릴리즈 노트만 갱신하고 건너뜀**. 하루 실제 교안 수는 출시량에 따라 달라짐.
- **출시일 관리(릴리즈 노트)는 필요함**: 교안과 별개로 "언제 무엇이 나왔나"가 쌓여야 ① 중복 교안 방지 ② 교안 타임라인 자동 근거 ③ 재검토 시점 판단 ④ 아직 교안이 없는 출시(빈 칸) 파악이 가능함.

## 3. 교안 ID·버전·유효기간

- 교안 ID: `AI-<작성연도>-<작성월>-<주 카테고리>-<일련번호 3자리>` 예) `AI-2026-10-CAT01-002`
  - 일련번호는 같은 연·월·카테고리 안에서 1부터 증가
- 버전: `v1.0` 시작 → 문구·캡처 수정 `v1.1` → 기능이 크게 바뀌면 `v2.0`
- 유효기간: `checked`(교안 기준일) + `review_by`(기본 3개월 뒤)
- 기능 변경·종료를 발견하면 `notice`(⚠️ 변경 공지)를 채우고 버전을 올림

## 4. 배지·코드표 (요약)

- 학습자: `초급`(처음 사용) · `중급`(업무 활용 중) · `고급`(자동화·개발)
- 강사: `초보강사`(1년 미만) · `중급강사`(1~5년) · `고급강사`(5년 이상·설계자)
- 직업군: JOB-OFF 사무 · JOB-MKT 마케팅·소상공인 · JOB-EDU 교사·강사 · JOB-CRE 크리에이터 · JOB-WRI 작가 · JOB-DEV 개발·노코드 · JOB-DAT 데이터·연구 · JOB-BIZ 창업·1인기업 · JOB-PUB 공공·평생교육 · JOB-HLT 의료·돌봄(진단·처방 금지 안내 필수) · JOB-FAR 농업·제조·현장 · JOB-SEN 시니어 · JOB-STU 학생·취준 · JOB-GLB 외국인·다문화·한국어 학습자
- 카테고리: CAT-01 대화형 AI · CAT-02 프롬프트 · CAT-03 문서·오피스 · CAT-04 이미지 · CAT-05 영상·음성·음악 · CAT-06 리서치·분석 · CAT-07 코딩·노코드 · CAT-08 에이전트·자동화 · CAT-09 윤리·저작권·보안 · CAT-10 AI 교수법 · CAT-11 비즈니스·수익화 · CAT-12 도구 비교

## 5. 사실 확인 표시 규칙

| 표시 | 뜻 | 사용 예 |
|---|---|---|
| (출처·확인일) | 공식 문서로 확인함 | 요금, 출시일, 지원 요금제 |
| `[확인 필요]` | 공식 문서끼리 다르거나 화면 경로가 바뀌었을 수 있음 | 메뉴 경로, 버튼 이름 |
| `[미검증]` | 공식 발표만 있고 실제 동작을 확인할 근거가 없음 | 순차 출시 중 기능 |
| `[실험 기능]` | 회사가 실험·베타라고 밝힌 기능 | 가져오기·내보내기 |

공식 문서가 아닌 기사는 **보조 근거로만** 쓰고, 그 내용에는 출처 이름을 함께 적는다.

## 6. 교안 데이터 필드 (lessons/<ID>.json)

| 필드 | 필수 | 내용 |
|---|---|---|
| `id`, `version`, `stage` | ✅ | 교안 ID, 버전, `standard` |
| `created_at`, `checked`, `review_by` | ✅ | 작성 시각(KST), 기준일, 재검토일 |
| `title`, `summary` | ✅ | "무엇을 만들 수 있게 되는가" 제목, 한 줄 요약 |
| `tool`, `feature`, `company`, `type`, `released` | ✅ | 서비스·기능명(공식 표기), 회사, `new`(신규 AI)/`update`(기존 AI), 기능 출시일 |
| `categories`, `jobs`, `learner_levels`, `instructor_levels` | ✅ | 코드표 기준 |
| `minutes` | ✅ | `{theory, practice, wrap}` — 비율 약 3.5 : 5.5 : 1 |
| `prerequisites`, `outcome`, `objectives` | ✅ | 준비물, 최종 결과물, 학습 목표 3개("~할 수 있다") |
| `pricing` | ✅ | `access`(free/freemium/paid), `summary`, `plans[{name,price,features}]`, `note`, `checked`, `sources` |
| `timeline` | ✅ | `[{date, text}]` 기능 변천사 (최소 1개, 출시일 포함) |
| `theory` | ✅ | `definition`, `analogy`, `comparison{headers,rows}`, `concepts[{title,body}]` 3개, `can[]`, `cannot[]`, `safety[]` 3개 이상 |
| `practice` | ✅ | `preview`, `follow[]`, `make_mine[]`, `challenges[{level,mission}]` — 단계는 `{title, minutes, do, prompt, expect, note}` |
| `wrap` | ✅ | `share`, `quiz[{q, options[4], answer(0~3), explain}]` 3개, `next[]`, 선택 `rubric[{criterion,high,mid,low}]` |
| `instructor` | ✅ | `timetable[{time,content,note}]`, `script[{label,text}]`, `plan_b[{situation,response}]`, `stuck[{issue,fix}]` 5개, `faq[{q,a}]` 5개 이상, `level_guide[{level,guide}]`, `pro_points[]`, `day_before[]` |
| `verification` | 선택 | `[확인 필요]`/`[미검증]` 메모 |
| `notice` | 선택 | ⚠️ 변경 공지 |
| `sources` | ✅ | `[{title, url, checked}]` 1차 출처 우선 |

## 7. AI 릴리즈 노트 (releases.json)

- 한 줄 = 출시 1건: `{id, date, tool, company, type, title, summary, source{title,url}, checked, lesson_id}`
- `date`는 공식 발표일(순차 출시면 첫 공개일), `lesson_id`는 교안이 있으면 연결, 없으면 `null`
- 매시간 작업이 주요 서비스(ChatGPT, Claude, Gemini, Copilot, Perplexity, NotebookLM, Midjourney, Runway, ElevenLabs, Cursor 등)의 **공식 릴리스 노트**를 확인해 빠진 항목을 추가
- 같은 기능의 후속 변경은 별도 항목으로 쌓음 → 교안의 `timeline` 근거가 됨
- 사이트 `releases.html`에서 월별로 보고, 교안이 없는 항목은 "교안 대기"로 표시
